 # 后端工程化与语义化重构计划

  ## Summary

  目标是把后端从“多个浅 Module 拼接”推进到“语义清晰、入口统一、高聚合低耦合”的结构：每个核心概念拥有一个深 Module，调用方只依赖稳定 Interface；实现细节、
  兼容分支和底层 Adapter 都收敛到模块内部。

  默认统一入口定义为两层：Gateway 统一通过一个 Run Launch Module 启动后端运行；Harness 统一通过 create_deerflow_agent 组装 agent，make_lead_agent 只保留为
  兼容外壳。每个 Phase 必须在 docs/IMPROVEMENTS/ 输出对应改造说明。

  ## Phases

  ### Phase 0 — 改进文档索引与架构词汇

  Scope:

  - 只新增 docs/IMPROVEMENTS/README.md。
  - 只定义后续 Phase 的文档模板、Module/Interface/Seam/Adapter 词汇和执行顺序。

  Constraints:

  - 不改 Python 代码。
  - 不改既有 docs 内容，只新增索引。
  - 每个后续文档必须包含 Scope、Constraints、Done when、Stop if。

  Done when:

  1. docs/IMPROVEMENTS/README.md 存在，并列出 Phase 1-6 的文档文件名。
  2. git diff -- docs/IMPROVEMENTS/README.md 只显示新增文档。

  Stop if:

  - 需要修改业务代码才能解释计划。
  - 发现已有 docs/IMPROVEMENTS 文档与本计划冲突。

  ### Phase 1 — 用户线程资源 Module

  Scope:

  - 只处理 Gateway 层线程资源访问：线程归属、用户 namespace、用户路径前缀、线程虚拟路径解析。
  - 重点覆盖 thread_ownership.py、线程/上传/产物/skill install 相关路由。
  - 输出 docs/IMPROVEMENTS/01-user-scoped-thread-resource.md。

  Constraints:

  - 所有线程资源访问必须先通过统一 Interface 获取 authenticated thread resource。
  - 不允许路由直接拼接用户 namespace。
  - 不允许路由在已知 user_id 时调用无用户作用域的线程路径解析。
  - 不改变现有 HTTP 路径和响应 schema。

  Done when:

  1. docs/IMPROVEMENTS/01-user-scoped-thread-resource.md 记录新 Module 的 Interface、Adapter 和调用方迁移规则。
  2. 线程 delete、uploads、artifacts、skills install 相关测试覆盖用户隔离。
  3. PYTHONPATH=. uv run pytest tests/test_thread_ownership.py tests/test_threads_router.py tests/test_uploads_router.py tests/test_artifacts_router.py
     tests/test_skills_custom_router.py -q 通过。

  Stop if:

  - 需要改变前端请求协议。
  - 发现匿名线程仍是必须支持的生产路径且无法归入该 Interface。

  ### Phase 2 — Runtime Context 与 Run Launch Module

  Scope:

  - 只处理 Gateway-mode run 启动和 runtime context 解析。
  - 收敛 context / configurable / metadata / Runtime.context 的优先级。
  - 输出 docs/IMPROVEMENTS/02-runtime-context-and-run-launch.md。

  Constraints:

  - thread_id、run_id、user_id、agent_name、app_config 只能通过统一 RuntimeContext Interface 解析。
  - Gateway route 只能调用 Run Launch Module，不复制 context merge 逻辑。
  - 保持 LangGraph Platform 兼容字段，不改变外部 wire shape。

  Done when:

  1. docs/IMPROVEMENTS/02-runtime-context-and-run-launch.md 明确 Run Launch Interface、RuntimeContext 字段和兼容策略。
  2. tests/test_gateway_services.py 不再手写复制 context merge 逻辑，而是测试统一 Interface。
  3. PYTHONPATH=. uv run pytest tests/test_gateway_services.py tests/test_run_worker_rollback.py tests/test_lead_agent_model_resolution.py -q 通过。

  Stop if:

  - LangGraph 版本差异要求同时保留两套互相冲突的入口语义。
  - 需要改变前端 context 或 config.configurable 的发送方式。

  ### Phase 3 — 统一 Agent 入口与 Canonical Middleware Chain

  Scope:

  - 只处理 agent 创建入口和 middleware 链装配。
  - 让 canonical middleware builder 成为唯一装配 Module。
  - 输出 docs/IMPROVEMENTS/03-canonical-agent-entry-and-middleware-chain.md。

  Constraints:

  - make_lead_agent 必须变成兼容外壳，不再手写完整 middleware append 顺序。
  - create_deerflow_agent 与 Gateway lead agent 必须共享同一个 ordering Module。
  - ClarificationMiddleware 始终最后；安全终止、loop detection、subagent limit 的相对顺序必须有测试锁定。
  - 不改 middleware 各自行为，只改装配归属。

  Done when:

  1. docs/IMPROVEMENTS/03-canonical-agent-entry-and-middleware-chain.md 记录统一入口、feature flags、ordering invariants。
  2. middleware_builder.py 被实际生产路径调用。
  3. PYTHONPATH=. uv run pytest tests/test_create_deerflow_agent.py tests/test_lead_agent_model_resolution.py tests/
     test_safety_finish_reason_middleware.py tests/test_loop_detection_middleware.py -q 通过。

  Stop if:

  - 发现 SDK 入口和 Gateway 入口必须长期保持不同 middleware 顺序。
  - 需要重写 middleware 内部行为才能完成入口统一。

  ### Phase 4 — User Extensions Config Module

  Scope:

  - 只处理 MCP/skills 的全局配置与 per-user override 合并。
  - 覆盖 skills loader、skills router、MCP router 的读写路径。
  - 输出 docs/IMPROVEMENTS/04-user-extensions-config.md。

  Constraints:

  - 全局 extensions_config.json 仍是开发者级配置，不能迁入用户对象存储。
  - 用户 override 只能通过 OpenDAL key helper 访问。
  - skills 与 MCP 必须使用同一个 effective extensions config Interface。
  - 不改变现有配置文件格式。

  Done when:

  1. docs/IMPROVEMENTS/04-user-extensions-config.md 记录合并顺序、错误处理和缓存刷新策略。
  2. skills/MCP enablement 测试证明同一用户 override 在两个入口行为一致。
  3. PYTHONPATH=. uv run pytest tests/test_skill_enablement_user_prefixed.py tests/test_mcp_config_secrets.py tests/test_mcp_client_config.py tests/
     test_skills_loader.py tests/test_skills_custom_router.py -q 通过。

  Stop if:

  - 需要修改 extensions_config.json schema。
  - 用户 override 与全局配置的合并规则无法在不破坏现有行为的情况下统一。

  ### Phase 5 — Custom Agent Store Module

  Scope:

  - 只处理 custom agent 的存储生命周期：名称规范、存在性检查、读写、删除、失败清理。
  - 覆盖 Gateway agent router、setup/update agent tools、agent config loader。
  - 输出 docs/IMPROVEMENTS/05-custom-agent-store.md。

  Constraints:

  - agent 名称 normalization 必须只有一个实现。
  - Gateway route 和 agent tool 必须走同一个 CustomAgentStore Interface。
  - OpenDAL key 布局不改变，除非文档明确迁移策略。
  - 不改变 /api/agents 响应 schema。

  Done when:

  1. docs/IMPROVEMENTS/05-custom-agent-store.md 记录 store Interface、OpenDAL Adapter 和失败清理规则。
  2. Router/tool 不再各自实现 YAML shape、exists、delete-prefix 逻辑。
  3. PYTHONPATH=. uv run pytest tests/test_agents_user_prefixed.py tests/test_custom_agent.py tests/test_setup_agent_tool.py tests/
     test_update_agent_tool.py -q 通过。

  Stop if:

  - 需要迁移已存在 custom agent 对象 key。
  - 发现 agent tool 与 Gateway route 必须保留不同名称规范。

  ### Phase 6 — Run State、Streaming 与 Persistence 深化

  Scope:

  - 只处理运行态后处理：final state 读取、checkpoint Adapter、stream protocol、RunStore record 映射。
  - 输出 docs/IMPROVEMENTS/06-run-state-streaming-persistence.md。

  - 不改变 SSE wire protocol。
  - 不改变 LangGraph checkpoint 存储 backend。
  Done when:

  1. docs/IMPROVEMENTS/06-run-state-streaming-persistence.md 记录 checkpoint Adapter、stream protocol Module、RunStore record Interface。
  2. final-state wait、title sync、rollback、stream replay 各有 Interface 级测试。
  3. PYTHONPATH=. uv run pytest tests/test_run_manager.py tests/test_stream_bridge.py tests/test_sse_format.py tests/test_run_worker_rollback.py tests/
     test_thread_runs_router.py -q 通过。

  Stop if:

  - 需要引入 Redis stream bridge 或改变多进程运行模型。
  - 需要修改前端 SSE 消费逻辑。

  ## Test Plan

  - 每个 Phase 先新增或调整聚焦测试，再重构实现。
  - 每个 Phase 完成后运行对应 pytest 命令。
  - Phase 3 和 Phase 6 完成后额外运行 PYTHONPATH=. uv run pytest tests/test_harness_boundary.py -q，确保 harness 仍不 import app.*。
  - 最终验收运行 cd backend && make test。

  ## Assumptions

  - docs/IMPROVEMENTS/ 是本次架构改进的唯一文档输出目录。
  - 统一入口默认分为 Gateway run launch 入口和 Harness agent creation 入口，不强行合并成一个跨层函数。
  - 本计划不改变 HTTP 协议、配置文件 schema、OpenDAL key 布局、LangGraph checkpoint backend。
  - 优先做能提升 Locality 和 Leverage 的深 Module；不做纯文件搬迁式重构。
