# Onboarding About Me 与 Style

日期：2026-06-03
状态：产品体验对齐草案

## 背景

当前产品已经有 Memory 系统，可以在长期交互中学习用户背景、偏好、纠正和近期关注点。现有结构包括 `workContext`、`personalContext`、`topOfMind`，以及分类为 `preference`、`knowledge`、`context`、`behavior`、`goal`、`correction` 的事实。

新的 onboarding 设想是在用户注册后提供两个初始化入口：

- **About Me**：用户主动填写的科研画像，让 Agent 从第一轮对话开始就知道用户的职业、课题、研究场景和协作需求。
- **Style**：用户主动选择的回复风格，用于调整 Agent 的默认表达方式，例如基本语调、Emoji 表达增强、表格表达增强、解释深度等。

这里的核心问题不是“它们是否重复 Memory”，而是要区分：onboarding 捕获用户主动声明的默认信息，Memory 捕获系统从长期交互中学习出的变化与补充。

## 产品定位

### About Me

About Me 应该被理解为“声明式科研画像”，不是泛泛的个人简介。它回答的问题是：Agent 在开始科研协作前，应该先知道我是谁、我在做什么、我希望它怎样理解我的研究处境。

建议字段：

- 身份或角色：本科生、博士生、PI、工程师、研究员、产品构建者等。
- 研究领域：大方向、细分方向、研究对象、材料体系、方法体系等。
- 当前课题：论文课题、活跃项目、基金方向、实验问题、产品中的科研工作流。
- 方法与资产：数据集、仪器、模型系统、软件栈、文献库、实验流程。
- 协作需求：文献综述、假设打磨、实验设计、数据分析、论文写作、代码实现、汇报展示、项目管理。
- 约束与边界：语言偏好、引用要求、可复现要求、隐私边界、Agent 不应该默认假设的内容。

它和现有 Memory 的 `workContext`、`personalContext`、`topOfMind`，以及 `context` / `knowledge` / `goal` 类 facts 有明显重叠。但补充点也很明确：About Me 是显式声明、高置信度、注册后立即可用，并且应该由用户随时编辑。

### Style

Style 应该被理解为“账户级回复控制面板”。它回答的问题是：Agent 默认应该用什么表达方式和我协作。

建议控制项：

- 语调：普通、正式、简洁、解释型、鼓励型等。
- Emoji：关闭、轻量、增强。
- 表格：仅必要时使用、偏好比较类表格、尽量不用表格。
- 结构：自然段优先、必要时 bullets、大纲化优先。
- 解释深度：简短、平衡、深入。
- 科研严谨度：普通、引用优先、审稿人视角、教学模式。
- 语言：跟随用户语言、中文优先、英文优先、必要时双语。

它和现有 `tone_style` 以及 Memory 中 `preference` / `behavior` 类 facts 有重叠。但 Style 的补充点是确定性：它应该是用户明确控制的设置，而不只是 Agent 从对话里推断出来的记忆。

## 与现有 Memory 的关系

产品上要避免出现多个互相竞争的“偏好来源”。更清晰的心智模型是：

| 层级 | 来源 | 用途 | 置信度 | 更新方式 |
|---|---|---|---|---|
| 声明式画像 | About Me onboarding 与后续 profile 编辑 | 稳定科研身份、课题、研究处境 | 高 | 用户编辑 |
| 声明式风格 | Style onboarding 与后续 settings 编辑 | 默认回复方式 | 高 | 用户编辑 |
| 学习型 Memory | 对话后的 Memory updater | 近期关注、演化中的偏好、纠正、长期目标 | 按 confidence 分级 | Agent 提取，用户可编辑 |
| 运行时控制 | 每个 thread 或浏览器本地设置 | 临时模型、模式、session 选择 | session / device 级 | 用户选择 |

建议优先级：

1. 系统安全、平台人格和运行时规则永远优先。
2. 用户显式 Style 优先于 Agent 推断出的表达偏好。
3. 用户显式 About Me 优先于 Agent 推断出的背景信息。
4. 学习型 Memory 用于补空白、补近期上下文、记录纠正。
5. 运行时控制可以在当前 thread 临时覆盖账户默认值。

因此，onboarding 不应该成为一套平行 Memory，而应该是 Memory 的“初始种子”和回复行为的“显式控制层”。

## 产品体验原则

这个 onboarding 应该让用户感觉是在“设置一个科研协作者”，而不是填写 CRM 档案。

- 必须可跳过。用户应该可以先开始聊天，之后再补全。
- 问科研场景相关的问题，而不是泛泛收集个人信息。
- 使用短输入和选择控件，而不是一个巨大的空白文本框。
- 允许“不确定”和空答案。很多早期研究者的课题本来就是模糊的。
- Style 最好提供即时预览，因为用户更容易通过样例判断自己想要的表达风格。
- About Me 和 Style 应该能从 Preferences / Memory 入口继续编辑。
- 隐私边界要作为一等能力。用户应该可以删除、导出，或标记某些信息不用于未来个性化。

## 建议首轮流程

### Step 1：About Me

用 4 到 6 个问题完成：

- “你当前最接近哪种身份？”
- “你正在研究或推进什么方向？”
- “有哪些方法、数据、工具或文献背景是 Agent 应该知道的？”
- “你通常希望 Agent 帮你做哪些科研相关工作？”
- “有什么语言、引用、隐私或假设边界需要注意？”

最后一个问题要显式邀请用户写边界：哪些东西保密、引用要多严格、使用什么语言、哪些假设不要默认成立。

### Step 2：Style

Style 应该尽量用紧凑控件表达：

- 语调 segmented control。
- Emoji toggle 或三档选择。
- 表格偏好 segmented control。
- 解释深度 slider 或三档选择。
- 科研严谨度 selector。
- 语言偏好 selector。

建议用同一个科研小问题展示 before / after 预览。预览只展示表达变化，不承诺能力变化。

### Step 3：确认

确认页只总结三件事：

- 将保存“科研画像”。
- 将保存“回复风格”。
- 之后可以继续编辑、导出或删除。

不要说“Agent 会永远记住你的一切”。更准确的产品承诺是：Agent 会把这些作为默认上下文和表达设置来使用，用户仍然拥有控制权。

## 产品决策

1. About Me 应该种到 Memory 兼容的用户上下文里，但 UI 上呈现为 profile。
2. Style 不应该只作为 Memory fact 存在，而应该是确定性的设置面板。
3. 学习型 Memory 可以继续从交互里学习，但不能静默覆盖用户显式设置。
4. 用户应该能分开查看、编辑、清空、导出：声明式画像、声明式风格、学习型 Memory。
5. 第一版应该围绕科研协作优化：身份、课题、方法、资产、约束、输出偏好。

## 待讨论的实现问题

- About Me 是直接写入现有 `user_memory` JSON，还是单独建 profile 存储，再渲染进同一条 prompt 路径？
- Style 是扩展现有 `tone_style` enum，还是升级成账户级 style object？
- 当 Memory 学到的风格偏好和显式 Style 冲突时，如何展示和解决冲突？
- onboarding 是否应该创建 `source: "onboarding"` 的高置信度 facts，还是只更新结构化 summary 字段？
- profile / style 是否纳入 `/api/memory/export`，还是通过更大的 user settings export 处理？
- onboarding 只在注册后出现，还是也作为“Improve agent personalization”入口开放给老用户？

## 后续实现方向

初步实现方向可以先按这个边界讨论：

- About Me 靠近 Memory，因为它是语义化用户上下文。
- Style 靠近账户设置和 prompt 构建，因为它是确定性的回复控制。
- 增加 provenance，区分用户声明的信息和 Agent 推断的信息。
- 最终通过一条可预测的 prompt 路径注入，让显式设置优先于学习型 Memory。

这样产品解释会很清楚：告诉 Agent 你是谁，选择它怎么回应你，然后让 Memory 持续学习那些会变化的部分。
